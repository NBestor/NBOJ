## 二、内容设计

平台围绕题目、作业、班级、学生、提交、诊断与标准知识库组织内容。

学校管理区分平台管理员、学校管理员与教师；教学资源归教师，名单、作业、题目版本与学校额度各有明确范围，详见[学校与教师管理](功能设计/学校与教师管理.md)。

1. 题目与作业：题目包含题面、测试用例、评测语义和知识关联；作业组织班级需要完成的题目，区分草稿与可发布状态。
2. 提交与诊断：每次提交保存学生、题目、作业等归属，以及代码、判题结果、测试证据和完整诊断版本。错误点与提升点分别记录，不能只保留第一条。
3. 学习证据：问题持续、复发、解决、成长状态和班级统计，是从提交与学习行为计算的结果；保留比较基线、身份与版本，不覆盖原始事实。
4. 标准知识库：知识点、能力点、易错点、提升点与课堂、竞赛应用相互关联；保留稳定 ID、知识路径和历史引用。

字段、状态及具体边界见[提交与诊断](功能设计/提交与诊断.md)、[学生学习](功能设计/学生学习.md)和[标准库](功能设计/标准库.md)。

## 三、逻辑设计

学生提交代码后，系统保存判题事实并运行诊断；学生据此修改、说明或继续练习，教师从同一批事实理解学习问题。

1. 发布：作业发布前检查题目与用例是否就绪；草稿允许不完整，正式发布由服务端重新核验。
2. 诊断：运行状态由后端保存，已完成阶段可以复用；失败保留真实判题和已有结果，不以本地模板伪装外部模型成功。
3. 成长：在同一学生、题目和作业范围内比较有效提交，区分重复提交、进步、问题转移、回退与无法比较；不由代码行数或一次模型判断决定成长。
4. 教学：班级、作业、题目、学生和具体提交逐级关联，统计口径由后端统一生成；教师校正绑定所查看的提交与反馈版本，不覆盖原 AI 快照。
5. 学习反馈：修改、说明和换题验证分别需要实际证据；可以说明观察到的变化，不据此断言 AI 带来了进步或学生已经掌握。

具体条件与例外见[学生学习](功能设计/学生学习.md)和[教师教学](功能设计/教师教学.md)。

## 四、交互设计

学生端优先说明当前任务、真实错误、提升方向与可执行的下一步；教师端优先呈现作业、学生问题与证据。

1. 学生再次进入题目时恢复已保存的反馈，可以查看历次提交和正式诊断版本，不因刷新页面重新生成。
2. 修改前后需要比较时，展示实际基线、问题变化与关键代码证据；曲线和比较视图取决于可用数据，不用装饰图表填补缺失。
3. 教师沿“班级 → 作业 → 题目 → 学生 → 提交证据”下钻，保留对象身份。统计允许重叠的集合，不画成互斥占比。
4. 长耗时任务离开页面后仍可恢复，展示真实进度与失败原因；provider、prompt、fallback 等研发信息不抢占学生主区域。
5. 数据不足时保留真实内容与缺失状态，不生成不存在的成长结论；窄屏按阅读顺序重排，已确认的页面结构不随相邻任务重做。

各页面的具体要求与场景见对应功能文档；操作命令从 [README](../README.md) 与[在线判题运行说明](../online-judge/README.md)进入。

## 五、技术设计

| 位置 | 职责 |
| --- | --- |
| `online-judge/src/main/java/` | Spring Boot 后端、领域模型、应用服务和 API |
| `online-judge/frontend/` | 学生端、教师端与管理工作台 |
| `online-judge/src/main/resources/db/migration/` | PostgreSQL schema 的 Flyway 正式迁移 |
| `online-judge/scripts/` | 构建、启动、部署、数据库备份与质量检查 |
| `online-judge/docs/` | 运行、迁移和排障说明，以及带日期的历史报告 |

1. 数据库结构：生产 PostgreSQL schema 通过新增 Flyway migration 演进，已发布迁移不修改，Hibernate 在正式环境只做校验。H2 只用于本地快速验证，不能代表生产结构。
2. 正式内容：题库和标准库进入数据库主库；旧 seed 只作测试夹具或受控迁移来源，不在普通启动时重新生成正式内容。
3. 诊断运行：按提交与生成版本保存运行阶段、证据和反馈快照，结构校验与领域服务控制正式写入。模型、prompt、schema 与投影来源需要可追溯；模型可用性和延迟以当前配置与实际调用为准。
4. 部署与路由：正式公开入口使用 `https://tuotuzju.com/code/`。公开路径由 [`route-ownership.json`](../online-judge/config/route-ownership.json) 约束，修改时同时核对资源、浏览器 API、代理、缓存与同域应用。
5. 发布：使用外部构建或已确认镜像，服务器启动与配置重载不隐式执行构建；保护数据库 Volume，生产动作与普通 Git 推送分开。

实现细节结合当前代码与数据库核实；运行命令与配置见[在线判题运行说明](../online-judge/README.md)，数据库操作见[数据库迁移说明](../online-judge/docs/database-migration-guide.md)，发布边界见[发布与运行](功能设计/发布与运行.md)。
