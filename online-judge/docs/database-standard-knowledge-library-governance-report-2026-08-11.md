# 标准库与知识库存量治理报告

## 结论

V11 后库规模已经足够大，本轮没有继续增条目，而是把最影响检索、解释和教学动作的存量债务直接治理掉。V12 保留全部稳定 code、父子层级和历史业务事实，只优化知识内容、正式修正协议、兼容边界和平铺快照。

| 指标 | 治理前 | 治理后 |
|---|---:|---:|
| 启用知识节点同名额外项 | 18 | 0 |
| 启用易错点同名额外项 | 1 | 0 |
| “由 AI 再生成”的元说明修正策略 | 358 | 0 |
| 可执行的旧版正式修正策略 | 0 | 348 |

| V11 场景教师动作去重数 | 48 | 96 |
| 规范错因与平铺快照差异 | 0 | 0 |

启用规模保持为：737 个知识节点、188 个能力、524 个易错点、185 个提升点、130 个场景。该历史恢复库比后续生产基线少 1 个 V3 提升点，本轮不借存量治理修补这项无关历史差异。

## 具体治理

### 1. 15 组同名知识改为路径语义名

共精修 33 个涉重名节点，同时更新名称、末级 path、描述、学习目标、典型问题和 aliases。原术语继续保存在 aliases，稳定 code 与引用不变。例如：

- “数据范围反推”拆清为“枚举范围与复杂度反推”“数据范围驱动的题型识别”“约束规模与复杂度预算”。
- “图结构”拆清为“图型题结构识别”“图输入合同识别”，数据结构章节继续使用规范主名“图结构”。
- “终止条件”拆清为模拟流程、对向指针和递归三个不同合同。
- “频次统计”拆清为定值域数组统计与键值映射统计。

这不是建立多套知识树，而是在统一树中让不同观察面可检索、可区分。

### 2. 358 个空心修正字段完成分层治理

- 348 个正式错因按 `mistake_type` 使用边界、复杂度、状态、建模、输入输出、调试、转移、类型和值域等 18 类协议，并嵌入该条目的实际名称与症状。每条都要求建立合同或假设、复现最小输入或首个偏差、执行修改和修复后复测。
- 10 个 `SK_COMPAT_*` 不补教学内容，统一明确为旧 ID 兼容路由：必须依据当前代码、判题事实和知识路径转到具体正式错因，无法映射就保留 `PARTIAL` 或证据不足。
- 同步 358 个平铺快照的名称、描述、误区、三级提示、证据信号、教师解释和使用边界；规范表仍是权威来源。

### 3. 重叠匹配错因与应用场景消歧

两个已有稳定 code 分别改为题意层的“未确认重叠语义就按模式长度推进”和实现层的“匹配后按完整模式长度推进导致漏计重叠”，不改提升路径和历史引用。

V11 的课堂场景保留形成性检查，48 个竞赛场景改为先核对约束画像与复杂度目标，再要求提交对拍、边界或评测记录。治理后 96 个场景拥有 96 条不同教师动作。

## 质量门禁

V12 事务内会阻断以下情况：目标基线缺失、同名仍存在、元说明仍存在、正式修正策略过薄、规范/快照不一致、迁移对不完整或动作相同、模板描述反弹、业务事实计数变化。迁移允许在已治理快照上原始 SQL 重放，但重放后仍执行同一套结果断言。发布审计脚本增加同名、修正协议、兼容边界、快照和场景差异七组长期指标。
